# Coverage Manifest

This manifest maps every behavior entry in [specs/testing.md](../specs/testing.md) to the tests that exercise it. Update it in the same change that adds or alters spec behavior or tests. The Tests column uses globally unique names from the deterministic `unit` Vitest project and stable case IDs from the live eval registry; grep a name or case ID to locate its definition.

Status values:

- **covered** — the entry's required cases have verifying assertions.
- **partial** — some required cases are proven; the Missing column lists the rest.
- **uncovered** — no test asserts the behavior.

Audit summary (2026-09-01): 146 entries — all covered. Every one of the 676 non-skipped tests within the `__tests__/` and `web/__tests__/` inventory scope is cited by at least one entry.

The first audit (2026-07-29) matched the inventory against the suite as it stood and left 11 partial and 2 uncovered entries. Those 13 gaps have since been closed by 17 added tests, so every entry now names verifying assertions.

Writing them surfaced one defect: every trigger-stage probe materialized a run workspace it never used, leaving an empty directory per probe under the artifact root. `disp.workspace-materialization` now supplies the Arcade process directory for trigger work, and `run.workspace-pruning` covers the startup sweep for abandoned run directories.

Provider advancement validation (2026-10-14): ARM static checks and the Arcade unit suite pass, with 865 tests passed and 2 pre-existing instruction-batching cases skipped. The provider, interruption, replay, time, cleanup, and resume cases below have passed behavioral validation, including deferred sleep completion through the real hub. Earlier audit counts describe the prior suite.

Worker report refactor (2026-10-13): the four report categories, SDK signals, and backend disposal are implemented with deterministic evidence below. Host issuance, frontier admission, hub cancellation, cleanup, and publication failure are covered by the interruption tests below. Live-provider qualification is reported separately.

## Spec Issues Found During Audit

Resolved while closing the gaps:

1. **`docs/service-apis.md` named the roles accessor twice, and disagreed with itself.** The heading read `knownConsumerRoles()` while the signature below it read `knownWorkerRoles()`. The heading now matches the implementation.
2. **Backend protocol sections pointed at a path that does not exist.** `docs/configuration.md` referred to backend protocol and activation-handshake detail in `specs/arcade.md`; arcade keeps those sections in `docs/arcade.md`. The four cross-references now name the real file.
3. **Handshake garbage collection looked unobservable.** The audit recorded that nothing exposes pending handshake count or age. That is true but not a blocker: `HandshakeStore` already takes `ttlMs`, and `ArcHostService` already accepts an injected store, so eviction is observable through a later `resolveHandshake` reporting `missing`. `HandshakeStore` was missing from `src/testing.ts` even though `ArcHostServiceOptions.handshakes` referenced it; exporting it closed that surface gap and made the case writable with no testing-only accessor.
